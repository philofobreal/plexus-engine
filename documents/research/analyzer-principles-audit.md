# Analyzer principles audit — algorithm 6, 2026-10-10

Scope: offline DSP, timing, feature interpretation, sections/semantics and the VJ/XR consumer contracts. This is a code-backed audit with targeted synthetic diagnostics, not an accuracy study of recorded music. Findings are classified as demonstrated defects, demonstrated contract gaps or design limitations. Priorities are development order, not a claim that every symptom has affected a real track. Existing local changes from the preceding improvement cycle remain intact.

## Foundations that should be retained

The headless analyzer and thin worker support deterministic fixtures and isolate DSP from playback/rendering. Fixed-Hz bands, the separate long-window low-frequency extractor, explicit beat/bar arrays, alternative tempo candidates and silence/percussive gates are useful foundations. Novelty already uses prefix sums and a time-based contrast window. Semantic/automation/gameplay ownership is explicit, and chart generation preserves published event timestamps rather than snapping them to beats. The lab records PCM/source/data/model identity and keeps oracle predictions distinct from truth. These are strengths to extend, not replace with a monolithic external library.

## DSP and timing findings

| Finding | Source / demonstrated scope | Strategy |
| --- | --- | --- |
| **P0: input/FFT guards are incomplete** | Headless `analyzeAudio` has no input contract check. Detailed diagnostics from FFT/FeatureExtractor show noninteger/NaN FFT sizes passing the bitwise guard and Infinity PCM yielding nonfinite main descriptors. Browser decode and lab bridge constrain common paths, so malformed-input findings primarily concern the public headless boundary. | Validate finite nonempty PCM, integer positive sample rate, valid power-of-two FFT length and hop policy at explicit entry points; test short and zero-length semantics. |
| **P0: no-overlap Hann blind positions** | [FeatureExtractor](../../src/analyzer/FeatureExtractor.ts#L146) uses FFT length equal to hop, and Hann endpoints null spectral evidence. Twenty-three ideal clicks every 21 hops yield no onset/tempo/beats at offsets 0/1023; the same clicks at offset 512 yield 123 BPM and 23 beats. This proves a frame-phase defect for short attacks, not a real-corpus failure rate. | Separate FFT window and hop, use overlapping windows, measure every sub-hop offset and audible-onset timestamp bias; retain sustained-tone negatives. |
| **P0: main feature tail is omitted** | [FeatureExtractor](../../src/analyzer/FeatureExtractor.ts#L113) and [LowFrequencyExtractor](../../src/analyzer/LowFrequencyExtractor.ts#L22) floor frame count. A synthetic 8704-sample clip with an impulse in the final 512 samples has zero main features there. True published duration still includes the remainder. | Declare padding/partial-frame policy and last-frame support; preserve true sample duration and sample clock. |
| **P0: low-level flatness violates its mathematical range** | [FeatureExtractor](../../src/analyzer/FeatureExtractor.ts#L248) uses geometric mean of `mag+epsilon` divided by unstabilized arithmetic mean. Near-silent noise diagnostics give flatness 10.64–11.48; mathematically consistent positive-input geometric/arithmetic flatness is ≤1. Silence gates mitigate some consumers. | Apply one physically defined stabilized spectrum to numerator and denominator; declare below-floor/unknown behavior, amplitude invariance and quiet-noise tests. |
| **P1: smoothing changes with clock** | [analyzeAudio](../../src/analyzer/analyzeAudio.ts#L53), [TemporalSmoother](../../src/analyzer/TemporalSmoother.ts#L1): alpha is per frame. Alpha 0.1 has time constant 220.4 ms at 44.1 kHz/H1024, 101.2 ms at 96 kHz/H1024, 881.5 ms at 22.05 kHz/H2048. | Specify tau in seconds and derive alpha from H/fs; assess energy/novelty/cue delay before promotion. |
| **P1: fixed FFT resolution limits spectral identity** | Default N1024 gives 43.07 Hz bins at 44.1 kHz. Main 20–60 Hz evidence has little bin support; the independent long-window low-frequency path improves body estimates but does not automatically repair all main percussive/identity features. | Multi-resolution evidence with a shared clock; low-frequency sustain/body and short attack evidence stay distinct. |
| **P1: a global tempo scaffold can drift through gaps** | BeatTracker synthetic 60 s pulse tests with a 36 s silent gap show up to 248 ms silent-gap phase error for fractional periods. Active and silent regions must be scored separately; this does not establish active-region musical accuracy. | Local interval/phase model, uncertainty growth in extrapolation, reacquisition after gaps and tempo changes; measure continuity/drift, not BPM only. |
| **P1: normalized novelty need not imply a discrete change** | [NoveltyAnalyzer](../../src/analyzer/NoveltyAnalyzer.ts#L40) uses a time-based contrast and normalization. Smooth ramp diagnostics produce 11/59/181 generic peaks over 10/60/180 s. This is a peak/prominence risk; final production section errors were not asserted. | Plateau/prominence tests, absolute contrast/support floor, separate ramp trend from discrete boundary; retain good prefix-sum implementation. |
| **P1: metrum is assumed** | [GridAligner](../../src/analyzer/GridAligner.ts#L125) sets four beats per bar. Downbeat evidence is heuristic and global. Beat/bar consumers cannot assume arbitrary meter support. | Explicit meter hypotheses/support status, separate downbeat confidence and local reliability; measure odd-meter and ambiguous-accent cases before advertising support. |

FFT positive-length numerical diagnostics also compared transform output with an independent DFT: worst reported absolute error about 1.7e-6. The transform itself is not implicated in the window-phase or invalid-size defects.

The long-window low-frequency extractor already uses sensible window-power scaling and seconds-based smoothing. Its centered support can precede an attack: the 40 Hz/1 s diagnostic first crosses flux 0.1 near 0.929 s at 44.1 kHz. This is offline temporal support, not a causal attack timestamp. Any future use for XR onset anchoring must retain that distinction.

The global tempo resolver also needs a documented decision boundary. [TempoEstimator](../../src/analyzer/TempoEstimator.ts#L83) pools local evidence; [GridAligner](../../src/analyzer/GridAligner.ts#L235) can consider candidates without an explicit closeness/metric-relation guard against the original winner. A 120→174 BPM synthetic envelope selects 87 BPM, matching 50% of late onsets within 70 ms; the resolver promotes candidate score 0.1458 over 120 BPM score 0.4312. This demonstrates policy behavior, not a uniquely correct global BPM for a tempo-changing track. Restricting candidates must retain the existing fast-tempo resolution tests.

## Representation and musical inference findings

| Finding | Source / reproduction | Strategy |
| --- | --- | --- |
| **P0: host/lab channel parity differs** | [AudioEngine](../../src/audio/AudioEngine.ts#L139) analyzes channel 0; [lab decode](../../research/analyzer-lab/src/plexus_analyzer_lab/audio.py#L25) averages channels. For L=x/R=-x the host sees x, lab sees silence. Web Audio may also decode/resample to context rate, while lab preserves WAV rate. Same-PCM comparisons inside the lab remain valid, but are not proof of host stereo/decode parity. | First benchmark exact host-decoded PCM and record channel/rate policy. Then evaluate a shared stereo policy; consider channel-power/onset fusion for anti-phase safety rather than hiding the change inside DSP. |
| **P1: `avgRms` changes meaning** | [SectionAnalyzer](../../src/analyzer/SectionAnalyzer.ts#L341): section `avgRms` is min-max relative section energy; bar `avgRms` is mean block RMS/typical RMS. Constant-RMS 0.25, typRms 0.5 yields bar avgRms 0.5 but section avgRms 0. [transitionDynamics](../../src/automation/transitionDynamics.ts#L85) consumes section avgRms as level evidence. | Separate physical/normalized RMS and arrangement-relative energy; duration/sample-weighted section statistics on realized boundaries; evaluate transitions again. |
| **P1: musical evidence and artistic emphasis share mutable storage** | [analyzeAudio](../../src/analyzer/analyzeAudio.ts#L89) calculates novelty/sections before [SpectralPivot](../../src/analyzer/SpectralPivot.ts#L22) alters published vocal/melody/fx/tension, then cues use the altered features. Diagnostic fx 0.4 becomes features.fx 0.53552 while frame.fxProj stays 0.4; melody projection is synchronized. | Define immutable measured/evidence features and a separately named artistic projection. Decide explicitly which representation cues, structure, VJ and XR consume; do not simply reorder the pipeline and create a feedback loop. |
| **P1: block-aligned buildup has broad temporal support** | [DramaturgyBuilder](../../src/analyzer/DramaturgyBuilder.ts#L49), [analyzeAudio](../../src/analyzer/analyzeAudio.ts#L105): average over eight-bar spans rooted at track zero. A controlled 40 s pressure step changes the 32 s probe from 0.018 to 0.144835 when aligned to 32 s blocks. | Local buildup trajectory and broad anticipation envelope need different names/support. Alignment should follow actual beat/bar arrays when trusted; lack of causality is not itself a bug in offline prediction, but must not masquerade as an onset. |
| **P1: inference score is passed as confidence** | [FeatureClassifier](../../src/analyzer/FeatureClassifier.ts#L89) computes weighted/clipped spectral heuristics; [DramaturgyBuilder](../../src/analyzer/DramaturgyBuilder.ts#L293) uses melody/vocal magnitude as cue confidence, impact 1.0, break 0.85. [GridAligner](../../src/analyzer/GridAligner.ts#L460) averages heuristic component scores. | Preserve score semantics and task-specific calibration status; unknown probability remains unknown. Event, local beat, downbeat, boundary and role confidence are separate. |
| **P1: label uncertainty disappears downstream** | [TrackSection](../../src/types/index.ts#L954) has no label confidence/alternatives. [NarrativeEngine](../../src/semantics/NarrativeEngine.ts#L53) deterministically maps labels and refines them by context; [MotifPlanner](../../src/semantics/MotifPlanner.ts#L78) gates subdivisions by global timing confidence. | Carry ambiguity/reasons and local reliability; graceful coarse choreography for weak evidence. Narrative intensity is artistic output, not a stronger posterior on the musical label. |
| **P2: similarity is not motif identity** | [DramaturgyBuilder](../../src/analyzer/DramaturgyBuilder.ts#L320) matches section energy, density and dominantFeature. Pattern occurrence confidence increases with repeat index. | Acoustic recurrence descriptor/beat-synchronous similarity with independent labels before claiming motifs; retain coarse arrangement similarity under its actual meaning. |
| **P2: downstream frame time is inferred** | [cueEvidence](../../src/semantics/cueEvidence.ts#L17), [transitionDynamics](../../src/automation/transitionDynamics.ts#L99): duration/frame-count substitutes for H/fs because TrackAnalysis lacks sampleRate. A 441777-sample/H1024 fixture accumulates 9.80 ms disagreement at the last frame. For floor framing the discrepancy is bounded below one hop; it is not arbitrary long-track drift. | Add explicit frame step/origin/support in a coordinated contract update; preserve exact end duration and legacy fallback. |

## Consumer boundaries relevant to analyzer precision

- [RhythmScorePlanner](../../src/gameplay/RhythmScorePlanner.ts#L96) preserves onset timestamps but filters events for approach time, intensity, spacing and movement safety. Chart removals are not analyzer misses. [RhythmHandPolicy](../../src/gameplay/RhythmHandPolicy.ts#L48) assigns beat affinity within ±15% of the beat interval; this coarse attribution does not snap note time.
- [XrAppController](../../src/xr/XrAppController.ts#L284) passes overall timing confidence rather than separate beat/downbeat confidence. [RhythmPhrasePlanner](../../src/gameplay/RhythmPhrasePlanner.ts#L29) can use median onset spacing as a movement scaffold. It is generated choreography, not detected musical phrase truth.
- [RhythmJudge](../../src/gameplay/RhythmJudge.ts#L18) rejects backwards song time/large pose gaps and interpolates collision time. [AudioEngine](../../src/audio/AudioEngine.ts#L272) subtracts `(outputLatency || .02)+.01`, while play/seek publish unadjusted offsets. The next clock can retreat relative to a nonzero seek/resume offset. This is a contract inconsistency to validate with fake clocks and physical calibration, not proof of a particular device's latency.
- [PlexusRenderer](../../src/visuals/PlexusRenderer.ts#L361) dispatches overdue events as fresh impulses and decays per frame; [WormholeCanvasSource](../../src/visuals/WormholeCanvasSource.ts#L244) uses timestamp-age decay. For factor 0.88, time constant doubles from about 130 ms at 60 Hz to 261 ms at 30 Hz. Frame stalls/late dispatch can therefore look like analyzer mistakes. XR background [worker presentation compensation](../../src/visuals/WormholeWorkerSource.ts#L178) already exists; measure residuals rather than declaring it uncompensated.
- [XrSectionCallout](../../src/xr/scene/XrSectionCallout.ts#L44) synthesizes a four-beat countdown relative to section start using a constant local interval. A non-beat boundary can produce a musical-looking countdown without actual beat alignment. Section labels also influence [scoring](../../src/gameplay/RhythmScoring.ts#L107) without label uncertainty.

These consumer changes must remain separately owned. Analyzer thresholds should not absorb playback/render/input defects. XR data should preserve original acoustic time, local reliability and selection reasons; consumer policies may then choose safe coarser behavior.

## Optimization strategy

[analyzeAudio](../../src/analyzer/analyzeAudio.ts#L99) searches bars with `find` for each frame: O(F·B), replaceable by an ordered cursor after interval semantics are tested. [DramaturgyBuilder](../../src/analyzer/DramaturgyBuilder.ts#L34) repeats range averages: replaceable by prefix sums after boundary/empty-window parity. Full-array quantile sorts, object-heavy frame/spectrum output and additional FFT passes require measured profiling; do not assume they dominate every track.

Record per-stage wall time and peak memory on fixed 30/180/600 s tracks, and algorithmic scaling separately from noisy runtime measurements. Optimize one stage at a time, preserve exact/tolerance-defined outputs, and measure worker transfer/normalization cost. Keep no-DSP-in-render, bounded state and one owner for transport/schema changes. A richer classifier is valuable only after candidate recall, clock precision and runtime budgets are known.

Two further high-value profiling candidates are [per-frame static perceptual-bin overlap](../../src/analyzer/FeatureExtractor.ts#L353), which can precompute sparse weights, and [restarted onset/beat scans](../../src/analyzer/GridAligner.ts#L503), which can use an ordered two-pointer traversal. The low-frequency branch performs about 25 large FFTs per second: profile it separately before any downsampling, with anti-aliasing/band-response validation. Diagnostic loader wall times are not production performance measurements.

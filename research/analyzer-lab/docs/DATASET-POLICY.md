# Dataset and evidence policy

Dataset manifests contain references and metadata, never audio bytes. Paths resolve relative to the manifest; external references are preserved but benchmark runs currently require local WAV assets. No network loader or auto-download is provided. The Slakh-like example is hypothetical, not a grant or actual Slakh annotation. Check the dataset's own license/source and allowed research use before supplying assets. Library/loader license and dataset license are independent.

Evidence categories stay distinct: `ground_truth`, `oracle_prediction`, `pseudo_label`, `plexus_prediction`, `human_annotation`. Human annotation is not automatically adjudicated ground truth, and oracle predictions never gain ground-truth status. Every canonical result declares evidence provenance.

Consensus is deterministic per event class: sort time/provider/confidence, anchor the earliest remaining event, cluster only within the configured total time diameter (no chaining), select at most one vote per provider, then use mean vote time. Eligible providers with supported but empty event output remain in the agreement denominator; unsupported providers do not vote. Agreement = unique voting providers / eligible providers. Confidence is the mean of reported vote confidence values only when every selected vote reports one; otherwise it remains null. Votes retain provider, original time and confidence, tolerance, algorithm, agreement and explicit false ground-truth status. With one oracle, agreement can be 1.0 and the result is still only a pseudo-label.

Training export currently emits positive onset windows only. Features are exact existing Plexus raw AudioFrame fields on its hop/sample-rate clock. It does not invent negatives, source labels or unavailable feature channels. Target provenance embeds canonical voting-provider provenance, track/hash and consensus settings. A missing successful Plexus/features/oracle output yields an empty JSONL with diagnostics.

Official manifest train/validation/test assignments take precedence. Otherwise SHA256(trackId + seed) deterministically chooses a track-level 80/10/10 split. Never split random neighboring frames. Keep stable track IDs across copies/versions; manifests reject duplicate IDs and known identical content across different splits, and benchmarks verify actual local hashes before execution. Hashing identical bytes cannot identify different encodings or remixes of the same underlying performance: curator grouping is still required. Do not fit to the test partition or tune tolerances after inspecting holdout scores.

Audio, datasets, stem WAVs, MIDI assets, models, environments, caches and runs belong to ignored local artifact directories. Only small schemas/configs/synthetic metadata/expected JSON are versioned. Dataset permissions govern whether oracle output/pseudo-labels can be exported, redistributed or used for training; this lab records permission notes and makes no legal guarantee. Future training tasks must review those notes before consuming outputs.

Future `mirdata` integration belongs at `datasets/manifest.py`'s `resolve_reference`/`load_manifest` adapter seam. It should emit this same manifest, verify dataset checksums/licenses and preserve official grouped splits. mirdata is intentionally not a core dependency.

The P0 [drum corpus contract](DRUM-EVENT-CLASSIFIER.md) adds explicit group IDs, complete class coverage and reviewed use permission for supervised fitting. Its model only learns negatives from complete reviewed ground truth/human annotations. Optional oracle consensus remains separate measurement evidence. See [reviewed MIDI import](DRUM-DATA-IMPORT.md) for tempo-map conversion, class mapping, audible onset alignment and Slakh MIDI duplicate grouping.

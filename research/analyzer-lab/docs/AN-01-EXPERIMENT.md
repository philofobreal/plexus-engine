# AN-01: signal, clock and level contract

Predeclared 2026-10-10 before implementation. Root is the single integration owner for analyzer, shared types and downstream projections. Audio playback/worker lifecycle and renderer code remain outside this experiment.

Hypothesis: valid finite PCM is fully represented, including partial final windows; analyzer and consumers use the same sample clock; bar/section RMS carries one explicit meaning; host/lab channel projection agrees. This is mathematical/contract correctness, not a new recorded-music generalization claim.

Baseline: current algorithm 6 checkout, including the preceding tonal-sustain fix. Freeze a local copy of analyzer/types and controlled diagnostics before edits. All previously inspected synthetic corpora and golden fixtures are known regression material. There is no new train/validation/test selection and no threshold/model search in this experiment.

Implementation choices:

- Public headless input is nonempty finite Float32 PCM within [-8,8], integer sample rate 1000..384000 Hz, and power-of-two hop/window 4..65536 samples. Invalid PCM is rejected, never silently zeroed or clipped. Finite decoded amplitude above 1 is permitted up to this declared headroom (also the LF branch's existing domain); arbitrary extreme Float32 amplitudes are not a supported signal. FFT length 2 remains valid for bare mathematical transform tests, but its symmetric Hann is unusable for analysis.
- The main window remains equal to the hop for this cycle. Frame count becomes ceil(L/H); last FFT is zero padded, RMS/ZCR use only real samples. LF arrays have the same count. Window-edge attack loss remains AN-02 work.
- Publish an optional feature clock: sample rate/count, hop/window, origin sample 0, window-start timestamps and zero-padding policy. True duration remains L/fs; last bar/section endpoint does not extend into padding. Legacy publications without a valid explicit clock retain duration/count projection.
- Publish sample-weighted physical amplitude RMS for each realized bar/section interval; `avgRms` is that amplitude divided by the existing typical block RMS and clipped to [0,1]. `peakRms` remains normalized maximum block RMS; arrangement-relative `energy` remains separately named. Do not change section-label thresholds.
- Lab defaults to channel 0, matching AudioEngine. Optional arithmetic-mean projection remains explicitly requested and recorded; no implicit resampling. Independent multichannel fusion remains future work.

Integration clarification after controlled regression inspection, before acceptance: a zero-padded end cutoff generated false tone hits and shifted the final beat of two known fixtures. Tail acoustic evidence remains published, but the incomplete last window abstains from accepted visual attacks and grid inference; it also stays out of complete-window typical/sustain references. This introduces no selected tonal threshold. The last partial-window onset eligibility remains AN-02 work (at most one hop of audio). Grid inference uses the complete-frame prefix and retains legacy behavior for feature sources without a sample count. Decoded f32le PCM hashes and projection metadata prevent mismatched historical/provider comparisons. This clarification is disclosed rather than retroactively presented as the initial hypothesis.

Required gates: deterministic finite output; invalid-input rejection before callbacks; valid radix-2 DFT parity; short/tail support; exact duration and bounded timestamps; mathematical RMS cases including unequal support; clock roundtrip/legacy/malformed fallback; stereo anti-phase/channel-0 parity; existing musical correctness/tonal negatives, consumer/schema/purity suites; production build and full Node tests, with known baseline failures disclosed; entire lab suite. Performance costs are one linear PCM-validation scan plus interval RMS aggregation; profile separately if they cause a measured regression.

Golden changes may be reviewed only after independent musical/correctness tests pass. A changed frame count due to previously omitted tail is intentional; changes in tempo, event counts or phase must be investigated individually. Never rerun the Bun-only golden-generation script or silently replace snapshots to hide failed evidence. Record exact before/after drift and any reviewed updates in the implementation validation record. No automatic deployment or drum-model promotion.
